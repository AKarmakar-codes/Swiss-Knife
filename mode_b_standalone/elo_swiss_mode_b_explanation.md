# Elo-Swiss Mode B Process Explanation

The `elo_swiss_mode_b.py` script implements **Mode B** of the Swiss Knife GSI strategy (Generative Step Inference). Mode B leverages an simulated Elo tournament to select the best candidate reasoning step generated by a draft model. Unlike Mode A, Mode B implements **unconditional acceptance**—meaning there are no verifier fallback checks and no hard quality acceptance thresholds. The tournament champion is accepted for every generation step.

## High-Level Pipeline

For each decoding step, the process consists of the following key stages:

### 1. Draft Candidate Generation
- The system starts by sampling `n` candidate reasoning steps in parallel from a fast, lightweight "Drafter" model.
- For each generated step, the model computes its log-probabilities ($\log \pi_{draft}$). 
- Depending on the configuration (`sigma_mode` and whether `use_tilted_elo` is enabled), the system might also compute log-probabilities using a stronger "Verifier" model ($\log \pi_{verifier}$).
- It calculates an estimated reward ($\mu_i$) using a DPO-Blade adapter and, optionally, an uncertainty proxy ($\sigma_i$) for each candidate.

### 2. Elo Tournament Match Mechanics
The candidates then enter a simulated Elo rating tournament to assess their relative quality. Matches between candidate pairs can be determined in two ways:

- **Probabilistic (Thurstonian Case-V):** Uses a standard normal Cumulative Distribution Function (CDF). The match becomes stochastic, enabling a lower-scoring candidate to occasionally win if the uncertainty ($\sigma$) is high. This promotes exploration and upset wins, justifying the tournament approach.
- **Bradley-Terry Sigmoid:** A deterministic, soft-sorting approach based simply on the reward scores. This is the default when the probabilistic mode is disabled and no uncertainty is tracked.

After each simulated match, the candidate Elo ratings are updated based on actual versus expected outcomes.

### 3. Champion Selection
Following the tournament rounds, a single winner (the champion) is chosen via a **softmax draw** over the combined logits, rather than a hard argmax (greedy) selection.

The logit for candidate $i$ is calculated as a combination of its final Elo rating and a blade reward term:
$$ \text{logit}_i = w_{\text{tournament}} \cdot \left(\frac{R_i - 1500}{T}\right) + w_{\text{blade}} \cdot (\mu_i - \lambda \cdot \sigma_i) $$

Here, $\lambda$ (`uwo_lambda`) acts as an uncertainty penalty during selection. High-variance (uncertain) steps are systematically down-weighted, reducing their probability of being drawn.

### 4. Unconditional Acceptance
The selected champion is instantly accepted, and its tokens are appended to the ongoing output. 
- Mode B entirely removes the "Verifier fallback" phase present in Mode A. 
- No quality gate triggers a rejection, guaranteeing lower latency since expensive Verifier resamples are completely avoided.

## Key Advantages of Mode B
- **Lower Latency:** By removing secondary verifier fallback rounds, inference time is purely limited to Drafter generation and Blade scoring costs.
- **Simplified Control:** Step quality is regulated organically through the tournament selection logic and uncertainty penalty ($\lambda$).
