# Reward Reasoning Models (RRM): Theory & Implementation Guide

This document provides a comprehensive technical overview of **Reward Reasoning Models (RRMs)** (Guo et al., May 2025: *Reward Reasoning Models*) and details how the official RRM strategy is implemented and benchmarked within the `Swiss-Knife` repository.

---

## 1. Theoretical Foundation of RRM

### 1.1 The Bottleneck of Opaque Scalar Reward Models
Standard reward models in RLHF map a prompt-response sequence (query, response) directly to a real-valued scalar score via a single linear head. This approach suffers from two primary limitations:
1. **Opaque Interpretability**: Scalar scores provide no causal explanation for why one response was preferred over another.
2. **Fixed Compute Budget**: Scalar reward heads cannot scale test-time compute to solve difficult or subtle alignment queries.

### 1.2 Formulating Reward Modeling as Reasoning
RRMs reframe reward modeling as an **autoregressive generation task**. Given a query and two candidate responses (Assistant 1 and Assistant 2), an RRM generates a Chain-of-Thought (CoT) reasoning trace before producing its final decision:

RRM(query, response_1, response_2) -> reasoning_trace -> verdict

where the verdict is either `\boxed{Assistant 1}` or `\boxed{Assistant 2}`.

### 1.3 Post-Training via GRPO (Rule-Based RL)
To train RRMs without expensive human CoT annotations, the paper uses **Group Relative Policy Optimization (GRPO)** with rule-based outcome rewards:
- **Accuracy Reward (R_acc)**: +1 if the model's boxed answer matches the ground-truth human preference; -1 otherwise.
- **Format Reward (R_format)**: +1 if the model adheres to the `\boxed{Assistant X}` structure; -1 if formatting fails.

Through RL exploration, the model self-evolves thinking patterns (including step-by-step breakdown, counterfactual checking, and safety verification) to maximize preference accuracy.

## 2. RRM Prompts & Rewarding Strategies

### 2.1 Official Pairwise Prompt Template (Appendix A.1)
The official system and user prompts enforce objective evaluation while explicitly counteracting common judge biases (such as position bias and verbosity bias):

```text
System: You are a helpful assistant in evaluating the quality of the responses for a given instruction...
User:
## Query
{query}

## Assistant responses
### Assistant 1
{response_1}

### Assistant 2
{response_2}

## Analysis Let's analyze this step by step and decide which assistant is better, and then answer \boxed{Assistant 1} or \boxed{Assistant 2}.
```

### 2.2 Multi-Response Selection: Knockout Tournament vs. Elo
When evaluating N candidate responses for a single query (Best-of-N inference):

1. **Knockout Tournament (Linear O(N) Complexity)** — **Official Standard**:
   - Candidates are paired into single-elimination brackets over log2(N) rounds.
   - Requires only N - 1 total pairwise RRM comparisons.
   - Serves as the primary inference-time selection method (Section 4.3).

2. **Elo Rating System (Quadratic O(N^2) Complexity)** — **Optional Ablation**:
   - Every candidate plays against every other candidate in a round-robin format.
   - Evaluated as an ablation in Section 4.5.1 and used during RL training over unlabeled pools.

## 3. Swiss-Knife Implementation Architecture

The RRM benchmark implementation in `Swiss-Knife` consists of two core components:

```
Swiss-Knife/
├── benchmarking/
│   ├── strategies/
│   │   └── rrm.py                # RRMGenerator class & CoT box parser
│   └── run_rrm_benchmark.py      # Main benchmark runner on HH-RLHF seed 42
├── docs/
│   └── rrm_explanation.md        # Technical explanation document (this file)
├── tribunal/
│   ├── inputs/harmlessness/
│   │   └── rrm.jsonl             # Output generated by RRM strategy
│   └── eval_results/harmlessness/
│       └── rrm_eval.csv          # Scored tribunal results
```

### 3.1 `benchmarking/strategies/rrm.py`
- **`RRMGenerator`**:
  1. **Candidate Generation**: Samples N candidate responses from the generator model.
  2. **Pairwise CoT Evaluation**: Evaluates pairs using `RRM_USER_TEMPLATE`, generating step-by-step reasoning tokens before outputting `\boxed{Assistant 1}` or `\boxed{Assistant 2}`.
  3. **Regex Parsing**: `parse_rrm_judgment()` extracts the winner index (1 or 2).
  4. **Knockout Tournament Execution**: Advances match winners through log2(N) rounds until a single champion response is selected.

### 3.2 `benchmarking/run_rrm_benchmark.py`
- Loads `Anthropic/hh-rlhf` (`harmless-base`, test split).
- Applies deterministic shuffle with `seed=42`.
- Formats and writes winner responses to `tribunal/inputs/harmlessness/rrm.jsonl`.
- Triggers Tribunal evaluation (`tribunal.tribunal.run_eval`) to compute final safety and quality metrics in `tribunal/eval_results/harmlessness/rrm_eval.csv`.

## 4. How to Run the RRM Benchmark

To run the official RRM benchmark on 50 prompts of the HH harmlessness test split (seed 42):

```bash
python benchmarking/run_rrm_benchmark.py \
    --num-prompts 50 \
    --seed 42 \
    --gsi-n 4 \
    --max-tokens 512 \
    --input-dir tribunal/inputs/harmlessness \
    --eval-dir tribunal/eval_results/harmlessness
```

To run Tribunal judge evaluation separately on an existing `rrm.jsonl` file:

```bash
python -m tribunal.tribunal.run_eval \
    --input tribunal/inputs/harmlessness/rrm.jsonl \
    --output tribunal/eval_results/harmlessness
```
